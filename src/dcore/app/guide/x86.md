# x86 and MSVC (PC, original Xbox)

Registers: eax return value; eax, ecx, edx scratch; ebx, esi, edi, ebp callee-saved; esp stack.

Calling conventions (read them off the call sites)
- __cdecl: arguments pushed right to left, caller cleans up (`add esp, N` after the call).
- __stdcall: callee cleans up (`ret N`). Win32 API calls.
- __thiscall: MSVC member functions; `this` in ecx, callee cleans up.
- __fastcall: first two arguments in ecx, edx.

Frames: `push ebp; mov ebp, esp; sub esp, N` with locals at [ebp-x] and arguments from [ebp+8]; with
frame-pointer omission (/Oy) everything is esp-relative and offsets shift with each push.

Matching MSVC (versions 4.x-7.1 for older games; the project fixes version and flags)
- /O2 vs /O1 changes idioms (`xor eax, eax`, `rep movsd`, intrinsic `memcpy`/`strlen`).
- Local declaration order and types change stack offsets and register choice.
- `switch` with dense cases becomes `jmp [table + eax*4]`; MSVC also builds byte index tables.
- x87 floating point: `fld`/`fstp`, compares via `fcomp` + `fnstsw ax` + `test ah, 41h`; float to int
  calls `__ftol` (older MSVC) unless the project uses other flags.
- SEH frames (`push -1; push handler; mov eax, fs:[0]`) and `mov [ebp-4], N` state updates come from
  C++ objects with destructors in scope or try/catch.
- Virtual calls: `mov eax, [ecx]; call [eax + off]`.

Annotation-based projects (reccmp) mark functions with comments such as `// FUNCTION: GAME 0x401000`
above each definition; keep them exactly as the project writes them.
